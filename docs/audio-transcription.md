# 音频转写说明

## “音频转译”在本项目中的含义

这里准确的技术名称是 **语音识别 / 音频转写（ASR）**：从音频生成同一语言的文字。中文语音默认生成中文文字，不负责把中文翻译为英文或其他语言。

原生字幕获取和音频转写是两种不同来源：前者读取网站已存在的轨道，后者让本地模型重新识别声音。输出的 `method` 会保留这个区别。

## 何时使用音频路线

获取脚本先查询原生字幕。没有可访问轨道、轨道需要当前不可用的登录权限，或者所有候选轨道都无法解析时，`--transcribe` 才会触发音频路线。

B站 DASH 播放可提供独立音轨，脚本优先下载低带宽音轨；若遇到只提供混合媒体的布局，则可能取得混合文件，再用 FFmpeg 提取音频。yt-dlp 通用路线使用 `bestaudio/best`。这条路线不会截图或识别画面文字。

没有说出来的屏幕文字、图表或代码不会出现在音频转写里；处理内容依赖画面的教程时，需要另行查看和理解画面。

## 本地识别设置

- 实现：`faster-whisper==1.2.1`，通过 CTranslate2 推理。
- 默认模型：multilingual `turbo`，在本地 CPU 上以 int8 运行。
- 默认语言：`auto`；中文视频可用 `--language zh`。
- 使用 VAD 过滤无语音片段，避免把长时间静音当作讲话。
- 模型下载位置在项目的 `.models` 下，后续复用。该目录不上传到 GitHub。
- 原始识别分段保存在工作目录的 `segments_raw.jsonl`，规范化输出另存到 `--out`。

`--device cuda` 是可选参数，需要兼容的 GPU、CUDA 与 cuDNN 环境；当前实测和默认路径使用 CPU。不要只因为电脑有独立显卡就假定 GPU 路径可用。

## 结果该怎样理解

`subtitles.json` 的每段包含 `start`、`end`、`text`；ASR 结果还包含平均 log 概率、无语音概率等识别信息。这些评分不能证明文字正确，尤其是陌生人名、产品名和英文缩写。

- 同音词、口音、背景音乐和多人交谈可能引起错字或漏词。
- 断句和分段数量由模型决定，与作者的画面字幕不一定一致。
- 时间戳是模型估计的分段位置，不是人工对齐的逐字时间。
- 音轨结尾有音乐或静音时，最后一个文字段落可能早于音轨总时长；这本身不能证明漏了一段话。
- 自动识别出可读文本，不等于内容中的事实和数字经过核验。

需要逐字准确时，回听对应音频，保留原始文本，并把修订依据另记。`--initial-prompt` 可传简短、已知的专名术语表，但不要传入预期全文诱导模型照抄。

## 速度和模型选择

本次约 203 秒视频在本机 CPU 上测试，small 模型约 37 秒、turbo 约 60 秒，均不含首次模型下载。small 的同音词误识别较多；因此默认用 turbo，速度优先时可显式用 small。

实际用时随 CPU、线程数、语种、讲话密度和音频质量变化。首次运行还需要下载模型；仓库源码不包含模型权重或示例视频。

## 已知依赖兼容问题

实测 `faster-whisper==1.2.1` 与 `av==19.0.1` 组合会报：

```text
open() got an unexpected keyword argument 'metadata_errors'
```

当前依赖固定为已跑通的 `av==16.0.1`。遇到网站适配问题可以单独更新 yt-dlp；不要为此同时升级全部识别依赖。

官方实现与参数参考：[faster-whisper](https://github.com/SYSTRAN/faster-whisper)。
